# 4. Інтерфейс

Інтерфейс складається з двох частин: вебсторінки, з якою працює глядач, і HTTP API, через яке сторінка (або будь-який інший клієнт) звертається до рекомендатора. У Docker їх обслуговують два контейнери. Сторінку роздає `frontend` (nginx, http://127.0.0.1:8000), він же проксує `/api/` до `backend` ([розділ 1.8](01-overview.md#18-розгортання-docker-compose)). У локальній розробці `python -m backend` роздає і сторінку, і API з одного процесу.

## 4.1. Вебінтерфейс

```mermaid
    welcome["Вітання і сім прикладів запитів<br/>(до першої репліки)"]

    panel["Бічна панель «Хід роботи агента»<br/>кроки поточного запиту"]

    header --> chat
    chat --> welcome --> user --> answer --> composer
    header --> panel
```

| Елемент | Поведінка |
|---|---|
| Перемикач джерела моделі | «Локальна модель» (за замовчуванням) і «OpenRouter», з назвою моделі. Джерело неактивне, поки не готове: OpenRouter — без `LLM_API_KEY`, локальна модель — поки її ваги завантажуються; підказка пояснює причину. Щойно локальна модель з'являється, сторінка вмикає її сама (протягом ≈ 10 хв; далі — після перезавантаження сторінки). Вибір запам'ятовується |
| Приклади запитів | Сім нетривіальних запитів українською, перевірених наживо на локальній моделі (README, «Демо-запити»); натискання одразу надсилає запит |
| Жанр | Жорсткий фільтр пошуку; назви жанрів українською |
| Вік, стать | Необов'язкові; модель враховує їх як м'яку підказку ([розділ 3.6](03-llm-and-tool-calling.md#36-промпт); вплив — [розділ 9](09-selection-parameters.md)) |
| Поле запиту | `Enter` — надіслати, `Shift+Enter` — новий рядок |
| Очікування | Індикатор із поточним кроком («Думаю над запитом…», «Обираю найкращі фільми…») — кроки приходять потоком, поки агент працює |
| Картка фільму | Постер (посилання на TMDB), назва, рік, зважений рейтинг ★, жанри українською, пояснення моделі «чому», згорнутий сюжет; без постера — значок 🎬 |
| Трейлер | Якщо модель вирішила його показати: заголовок «Оцініть атмосферу», пояснення моделі, мініатюра YouTube; відео (`youtube-nocookie.com`) вантажиться лише після натискання |
| Нова розмова | Очищає історію й панель; налаштування лишаються |
| Помилка | Червона картка з причиною і кнопкою «Спробувати ще раз». Причини розрізняються: немає зв'язку, помилка сервера (текст `detail`), обірваний потік, неочікуваний формат відповіді |
| Бекенд або модель ще запускаються | Якщо `/api/config` не відповідає (перший запуск будує каталог), сторінка показує «Сервер MovieHarbor ще запускається…». Якщо бекенд працює, але жодне джерело не готове (перший запуск завантажує локальну модель), — «Локальна модель ще завантажується…». Поле запиту вимкнене; сторінка перевіряє кожні 3 с і підключається сама. Після ≈ 10 хв очікування повідомлення радить переглянути журнал (`docker compose logs backend` або `ollama-init`) |

### Бічна панель «Хід роботи агента»

Панель — довідка для дослідження й спостережності; вона не заважає розмові. На широкому екрані вона праворуч, на вузькому висувається кнопкою «Хід роботи». Панель показує кроки **поточного** запиту і оновлюється з кожною реплікою. Під час роботи агента вона заповнюється наживо.

| Етап | Інструмент | Факти |
|---|---|---|
| 1. Запит до пошуку | `search_movies` | запит, який сформулювала модель (усі пошуки, якщо їх було два) |
| 2. Кандидати (12) | — | короткий список останнього пошуку: місце, назва, рік, смужка й число косинусної подібності; обрані моделлю позначено ✓ і порядковим номером |
| 3. Трейлер | `show_trailer` | лише якщо модель вирішила показати: фільм, показано чи не знайдено, причина |
| 3 або 4. Вибір | `recommend` | «Обрано N з 12 · місця за схожістю: …»; id, відхилені кодом, якщо такі були |
| ! Корекції | — | кроки з помилками, які модель виправила |

Заголовок панелі: джерело, модель, кількість звернень до LLM, час відповіді. Етап 2 разом з етапом 4 показує, що модель не обирає просто найближчих за подібністю: вона зважує весь запит.

### Стани репліки

```mermaid
stateDiagram-v2
    [*] --> Готовий
    Готовий --> Очікування: надіслати запит
    Очікування --> Очікування: крок агента (потік)
    Очікування --> Відповідь: подія answer
    Очікування --> Помилка: 4xx / 5xx / подія error / обрив
    Відповідь --> Готовий
    Помилка --> Очікування: «Спробувати ще раз»
    Помилка --> Готовий: новий запит
```

Під час очікування поле запиту лише для читання, а кнопки «Надіслати» і «Нова розмова» вимкнені, тож дві репліки не накладаються. Після помилки невдала репліка вилучається з історії, щоб репліки глядача й асистента чергувалися; повтор надсилає її знову. З історії надсилається не більше 20 останніх повідомлень.

### Принципи

- **Легкість.** Три статичні файли (`index.html`, `app.js`, `styles.css`), без збірки, фреймворків і зовнішніх шрифтів.
- **Безпека.** Усі рядки з API потрапляють у сторінку як текст (`textContent` через допоміжну функцію `h`), ніколи як HTML.
- **Приватність.** До YouTube сторінка звертається лише після натискання на трейлер. `localStorage` зберігає тільки налаштування (джерело, жанр, вік, стать).
- **Доступність.** Семантичні елементи, підписи полів, `aria-live` для розмови й панелі, `role="radiogroup"` для перемикача, керування з клавіатури, `prefers-reduced-motion`.
- **Теми й адаптивність.** Світла й темна тема за налаштуванням ОС; верстка від 360 px.
- **Атрибуція TMDB.** Сторінка містить обов'язкову примітку про використання TMDB API.

## 4.2. HTTP API

Інтерактивна документація OpenAPI — http://127.0.0.1:8001/docs (бекенд напряму) або `/docs` у локальній розробці. Адресу сервера задають `HOST` і `PORT`: типово `127.0.0.1:8000`; у контейнері бекенду `HOST=0.0.0.0` (`backend/Dockerfile`), а Compose публікує порт як `127.0.0.1:8001`.

| Метод і шлях | Призначення |
|---|---|
| `GET /api/config` | джерела моделі, жанри, розмір каталогу, трейлери |
| `POST /api/recommend` | одна репліка → відповідь агента одним JSON |
| `POST /api/recommend/stream` | одна репліка → кроки агента потоком, потім відповідь (NDJSON); його використовує вебінтерфейс |
| `GET /` | вебінтерфейс (лише коли поруч є `frontend/`, тобто в локальній розробці) |

### `GET /api/config`

```json
{
  "providers": [
    {"id": "local", "label": "Локальна модель", "model": "gemma4:e4b", "configured": true, "ready": true},
    {"id": "openrouter", "label": "OpenRouter", "model": "google/gemma-4-26b-a4b-it", "configured": true, "ready": true}
  ],
  "genres": ["Action", "Adventure", "…"],
  "movies": 2274,
  "trailers": true
}
```

`configured` — джерело назване в налаштуваннях (для OpenRouter — задано `LLM_API_KEY`). `ready` — джерело може відповісти зараз: локальний сервер уже перелічує модель у `GET /models` ([розділ 3.2](03-llm-and-tool-calling.md#32-джерела-моделі-локально-за-замовчуванням-або-через-api)). Ключі API не повертаються ніколи.

### `POST /api/recommend`

Запит:

```json
{
  "provider": "local",
  "messages": [{"role": "user", "content": "Пригодницький фільм про пустелю з епічними краєвидами"}],
  "viewer": {"age": null, "gender": null, "genre": null}
}
```

| Поле | Правило |
|---|---|
| `provider` | `local` або `openrouter` |
| `messages` | 1–50 повідомлень `user`/`assistant`, кожне 1–4000 символів; останнє — від `user` |
| `viewer.age` | 1–120 або `null` |
| `viewer.gender` | `female`, `male`, `other` або `null` |
| `viewer.genre` | жанр із `/api/config` або `null` |

Відповідь (скорочено):

```json
{
  "reply": "Ось кілька фільмів, де пустеля — справжній герой історії…",
  "picks": [
    {"id": 841, "title": "Dune", "year": 1984, "genres": ["Action", "Science Fiction", "Adventure"],
     "rating": 5.86, "overview": "…", "poster_url": "https://image.tmdb.org/t/p/w342/…jpg",
     "why": "Епічні краєвиди пустельної планети…"}
  ],
  "trailer": {"movie_id": 841, "title": "Dune", "youtube_key": "…", "reason": "…"},
  "message": {"role": "assistant", "content": "Ось кілька фільмів…\n\n[recommended: Dune (1984, id 841); …]"},
  "trace": {
    "provider": "local", "model": "gemma4:e4b", "llm_calls": 3, "latency_ms": 35100,
    "steps": [
      {"tool": "search_movies", "arguments": {"query": "Пригодницький фільм про пустелю…"},
       "outcome": "знайдено 12 фільмів; найближчі: …",
       "data": {"candidates": [{"id": 841, "title": "Dune", "year": 1984, "score": 0.61}, "…"]}},
      {"tool": "show_trailer", "arguments": {"movie_id": 841, "reason": "…"},
       "outcome": "трейлер «Dune» показано", "data": {"id": 841, "title": "Dune", "status": "shown"}},
      {"tool": "recommend", "arguments": {"reply": "…", "picks": ["…"]},
       "outcome": "прийнято 3: Dune, …; відхилено 0", "data": {"accepted": [841, "…"], "rejected": []}}
    ]
  }
}
```

`message` — репліка асистента у формі, яку клієнт додає в `messages` наступного запиту; сервер не зберігає стану розмови. `trace.steps[].data` — структуровані факти для панелі: кандидати з подібністю, статус трейлера, прийняті й відхилені id.

### `POST /api/recommend/stream`

Той самий запит; відповідь — `application/x-ndjson`, по одному JSON-об'єкту в рядку:

```text
{"type": "step", "tool": "search_movies", "arguments": {…}, "outcome": "…", "data": {…}}
{"type": "step", "tool": "show_trailer", …}
{"type": "step", "tool": "recommend", …}
{"type": "answer", "reply": "…", "picks": […], "trailer": {…}, "message": {…}, "trace": {…}}
```

Кожен крок надходить, щойно інструмент виконано. Останній рядок — `answer` (поля як у `POST /api/recommend`) або `{"type": "error", "detail": "…"}`, якщо модель не впоралася. Перевірка запиту (400, 422) відбувається до початку потоку, тож ці помилки мають звичайні коди HTTP.

### Коди відповіді

| Код | Коли | `detail` |
|---|---|---|
| 200 | відповідь агента (у потоці — також подія `error`) | — |
| 400 | обрано OpenRouter без `LLM_API_KEY` | українське пояснення |
| 422 | запит не відповідає схемі або невідомий жанр; до моделі запит не доходить | один рядок українською: назви полів («Некоректний запит: перевірте viewer.age.») або «Невідомий жанр: X» |
| 502 | модель недоступна, відповіла помилкою або не завершила відповідь (лише `POST /api/recommend`) | українське пояснення ([розділ 3.8](03-llm-and-tool-calling.md#38-обробка-помилок)) |

## 4.3. Код

| Файл | Роль |
|---|---|
| `frontend/index.html` | розмітка: шапка, колонка розмови, бічна панель |
| `frontend/app.js` | стан, запити до API, читання потоку, відповідь, панель кроків, очікування бекенду |
| `frontend/styles.css` | стилі, світла й темна теми, адаптивність, висувна панель |
| `frontend/nginx.conf`, `frontend/Dockerfile` | контейнер фронтенду: роздача файлів і проксі `/api/` без буферизації |
| `backend/api.py` | ендпоінти, моделі запиту й відповіді, `Recommender`, потік NDJSON |
| `tests/test_api.py` | контракт API, зокрема потік і помилки валідації |
| `tests/test_e2e.py` | сценарії в браузері ([розділ 10.6](10-testing.md#106-сценарії-e2e)) |
