# 12. Вимоги до системи

Розділ формалізує функціональні й нефункціональні вимоги, яким **фактично відповідає** реалізована система MovieHarbor. Функціональні вимоги сформульовано за стандартом інженерії вимог ISO/IEC/IEEE 29148:2018 [1]. Нефункціональні вимоги згруповано за характеристиками моделі якості продукту ISO/IEC 25010:2023 (SQuaRE) [2].

Кожна вимога має метод верифікації і посилання на тест, вимірювання або розділ специфікації. Структура відповідає технічному завданню кваліфікаційної роботи: терміни, призначення системи, функціональні вимоги, нефункціональні вимоги. Порівняння з подібними системами наведено в [розділі 11](11-related-systems.md).

## 12.1. Терміни та визначення

| Термін | Визначення |
|---|---|
| LLM-орієнтована рекомендаційна система | рекомендаційна система, у якій велика мовна модель (Large Language Model, LLM) формулює запит до пошуку, обирає об'єкти й пояснює вибір |
| Об'єкт рекомендації | фільм каталогу |
| Каталог | 2 274 фільми з метаданими й векторними представленнями (`data/movies.json`, `data/movie_vectors.npy`), побудований із набору The Movies Dataset ([розділ 2](02-data-and-embeddings.md)) |
| Користувач | особа, що формулює запит; **профіль користувача** — необов'язкові жанр, вік і стать (поле `viewer` в API) |
| Репліка | одне повідомлення користувача й відповідь системи на нього |
| RAG (Retrieval-Augmented Generation) | двоетапний пайплайн: відбір кандидатів (retrieval) і генерація, заземлена на кандидатах (grounded generation) |
| Ембедінг (векторне представлення) | 384-вимірний одиничний вектор тексту, отриманий моделлю ембедінгів `paraphrase-multilingual-MiniLM-L12-v2` ([розділ 7](07-embedding-model.md)) |
| Пул кандидатів | 12 фільмів, найближчих за косинусною подібністю до пошукового запиту |
| Агент | цикл, у якому LLM виконує виклик інструментів (tool calling): `search_movies`, `show_trailer`, `recommend` ([розділ 3](03-llm-and-tool-calling.md)) |
| Заземлення (grounding) | правило, за яким рекомендувати можна лише фільми з останнього пошуку; його перевіряє код, а не модель |
| Галюцинація (hallucination) | твердження моделі, не підкріплене даними системи ([розділ 8](08-hallucinations.md)) |
| Джерело моделі | локальна модель (`gemma4:e4b` в Ollama, за замовчуванням) або OpenRouter (`google/gemma-4-26b-a4b-it`) |
| Local-First | парадигма, за якої дані й обчислення за замовчуванням лишаються на пристрої користувача [3] |
| Трасування | кроки агента для поточної репліки, показані в бічній панелі «Хід роботи агента» |

**Методи верифікації** (за ISO/IEC/IEEE 29148 [1]):
- **Т — тест:** автоматичний тест у контролі якості ([розділ 10](10-testing.md));
- **Д — демонстрація:** живий прогін на стеку Docker;
- **В — вимірювання:** відтворюваний скрипт оцінювання;
- **І — інспекція:** перевірка коду або конфігурації.

## 12.2. Призначення і цілі створення системи

- **Функціональне призначення:** добирати фільми з каталогу за описом бажаного природною мовою (українською чи англійською), пояснювати вибір і, коли це доречно, показувати трейлер.
- **Експлуатаційне призначення:** один користувач на власному комп'ютері, без облікових записів. Усі компоненти запускає Docker Compose; дослідницький прототип (proof of concept) магістерської роботи.
- **Мета створення:** показати, що мала локальна LLM у ролі агента над семантичним пошуком дає заземлені й пояснені рекомендації в умовах холодного старту (cold-start), не передаючи даних користувача назовні.
- **Межі:** поза обсягом — облік користувачів, збереження історії на сервері, колаборативна фільтрація, векторна база даних і автоматична оцінка пояснень ([розділ 1.7](01-overview.md#17-межі-проєкту)).

## 12.6. Вихідна специфікація і реалізація

Вимоги цього розділу уточнюють попередню специфікацію системи, сформульовану до розробки. Частину її положень реалізовано інакше, частину не реалізовано:

| Положення попередньої специфікації | Реалізація | Обґрунтування |
|---|---|---|
| Локальна векторна база даних (ChromaDB, sqlite-vec) з наближеним пошуком (HNSW) | точний пошук у пам'яті процесу (NumPy) | для 2 274 фільмів пошук займає 0,4 мс, а метрики не мають похибки наближення ([розділ 2.6](02-data-and-embeddings.md#26-чому-без-векторної-бази-даних)) |
| Квантована Llama 3.2 3B (GGUF Q4_K_M), не більше 4 ГБ пам'яті | Gemma 4 E4B в Ollama (`gemma4:e4b`, ≈ 5,5 ГБ ваг) | модель підтримує виклик інструментів в Ollama; для слабшого обладнання є `gemma4:e2b` ([розділ 3.2](03-llm-and-tool-calling.md#32-джерела-моделі-локально-за-замовчуванням-або-через-api), [1.8](01-overview.md#18-розгортання-docker-compose)) |
| Англомовна модель векторизації (на зразок all-mpnet-base-v2) | багатомовна `paraphrase-multilingual-MiniLM-L12-v2` | запити українською знаходять англійські описи без перекладу ([розділ 7](07-embedding-model.md)) |
| Фільтри за роком випуску й мінімальним рейтингом | лише жанровий фільтр | рейтинг враховано під час побудови каталогу: у нього входять лише фільми з кількістю голосів не меншою за 95-й перцентиль ([розділ 2](02-data-and-embeddings.md)) |
| Резервний список від пошуку (fallback), якщо LLM не відповіла | повідомлення про помилку з кнопкою повтору (FR-14) | не реалізовано |
| Скасування генерації користувачем | — | не реалізовано; хід роботи видно в панелі, а запит обмежено тайм-аутом `LLM_TIMEOUT_S` |
| Перемішування кандидатів проти позиційного упередження (position bias) | кандидати подаються моделі за спаданням подібності | не реалізовано; у вимірюванні модель обирала й далекі позиції: середня позиція вибору — 4,5–7,2 з 12 ([розділ 9](09-selection-parameters.md)) |
| Обмеження контексту проти ефекту «втрати всередині» (lost in the middle) | 12 кандидатів, опис кожного до 200 символів | реалізовано ([розділ 3.10](03-llm-and-tool-calling.md#310-мала-локальна-модель)) |
| Повна ізоляція від хмарних LLM | за замовчуванням так (локальне джерело); OpenRouter — свідома альтернатива на вибір користувача | NFR-SE-03 |
